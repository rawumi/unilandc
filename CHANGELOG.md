# Изменения

## 2.2.0 (текущая)

### Новое

- Байткод-VM (`src/vm.c`): AST компилируется в инструкции, исполняет их стековый
  движок с регистрами для составных присваиваний. Покрыты переменные, функции и
  замыкания, `for`/`while`/`for in`, `try/catch/finally`, `throw`, шаблоны, массивы,
  объекты, индексы и поля, `++`/`--`, `+=` и родственные, `break`/`continue`, блоки
  `python {}`/`go {}`, `import`. Включается `UNILAND_VM=1`; при некомпилируемой
  конструкции исполнение откатывается на дерево. Ошибки, стек вызовов и `-t` ведут
  себя одинаково в обоих движках.
- Модули: `import "файл.uni"` вносит имена в текущую область, `import "файл.uni" as ns`
  кладёт их в объект. Путь считается от файла-импортёра, модуль выполняется один
  раз, повторный импорт берёт кеш, цикл — ошибка с понятным текстом.
- Стек вызовов в сообщении об ошибке: печатаются функция и строка вызова, от
  внутренней рамки к внешней.
- Флаг `uniland run -t` (`--trace`): в stderr печатается каждый выполняемый узел и
  вход/выход из функций.
- `docs/stdlib.md` — справочник всех встроенных функций с сигнатурами, краевыми
  случаями и примерами; в `docs/guide.md` добавлены разделы про модули и трассировку.
- `tools/run_all.py` — единый прогон всех наборов; `.github/workflows/ci.yml` —
  сборка и тесты на `windows-latest` для push в `main` и pull request.
- `tools/run_import.py`, `tools/run_trace.py`, `tests/import/*`, `tests/stdlib_demo.uni`
  и сверки `stdlib_demo.out.txt` — общий набор вырос на модули, трассировку и
  стандартную библиотеку.
- `tests/vm_smoke.uni` — замыкания, рекурсия, `try/finally`, циклы и объекты;
  `run_all.py` дополнительно прогоняет golden, модули, трассы и примеры с
  `UNILAND_VM=1`.
- Golden-корпус и токены скопированы в `tests/compat`: тесты работают в чистом
  клоне, без соседнего `../uniland-go`.
- Лицензия MIT с копирайтом эталонной реализации — `LICENSE`.

### GUI и медиа

- PNG, JPEG, GIF, BMP и ICO через GDI+; размер по-прежнему можно не указывать.
- Анимированный GIF: кадры переключает `WM_TIMER`, ресурсы освобождаются при
  закрытии окна.
- `gui_video(path, w, h)` — видео через MCI, окно встраивается в GUI и закрывается
  вместе с ним.
- Аргументы `gui_image`/`gui_image_button`/`gui_video` приведены к одному порядку:
  путь первым.

### Go

- Обратный мост `gofunc("pkg.Func")`: функция Go вызывается из UniLand, аргументы
  приводятся по типам параметров через `reflect`.
- Воркер кешируется в `%TEMP%\uniland-goworker-c` и пересобирается по хешу
  встроенного исходника, поэтому правки `goworker.go` больше не залипают.

### Скорость

- Имена переменных ищутся по хеш-таблице в окружении вместо линейного перебора со
  `strcmp`; окружения и `BigInt` выделяются из арен.
- Блок без объявлений больше не создаёт новое окружение; аргументы вызова до 8 штук
  не аллоцируются в куче; кадры VM держат стек и регистры внутри `Frame`.
- VM кэширует найденную переменную по инструкции с проверкой окружения.
- Итог: цикл на 1 000 000 итераций — 0,34 с на дереве и 0,26 с на VM (было 4,86 с),
  `fib(24)` — 0,12 с и 0,16 с (было 0,26 с).

### Исправления

- `BigInt` переведён на арену с тремя встроенными лимбами: на каждое число больше
  нет двух выделений кучи, `fib(24)` ускорился примерно на 10–20%. Значения
  по-прежнему не освобождаются — память живёт до конца процесса.

- Неизвестные escape-последовательности в строках сохраняются как есть, поэтому
  пути вида `C:\tmp` больше не ломают лексер.
- `read_file` срезает UTF-8 BOM.
- `build.bat` находит `vcvars64.bat` через `vswhere`, а не только по жёсткому пути.

### Переименование

- Проект переименован из `uniland-c` в `unilandc`; User-Agent HTTP-клиента —
  `unilandc/2.2.0`.

## 2.1.x

- Порт на C11: лексер, парсер, дерево-интерпретатор, длинная арифметика,
  стандартная библиотека, CLI, форматтер, LSP.
- Мосты Python, Go (yaegi) и C, WinHTTP, GUI на Win32, блоки `python { }` и `go { }`.
- Лёгкий синтаксис: `x = 5`, `if`/`while` без скобок, `for i in 0..3`.
- Сверка с эталоном: 16 golden-кейсов, дампы токенов, форматтер, LSP.
