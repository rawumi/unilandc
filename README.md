# unilandc

Порт интерпретатора UniLand 2.2.0 с Go на C11 (MSVC). Эталон — `../uniland-go`; корпус golden-кейсов и токенов лежит внутри репозитория, поэтому для тестов соседний проект не нужен.

Автор языка UniLand — rawumi (ранее name-cho).

Лицензия — MIT, см. `LICENSE`; текст сохраняет копирайт эталонной реализации.

## Сборка

```
build.bat
```

Нужен MSVC (Build Tools 2019 или новее). `build.bat` сам находит `vcvars64.bat`
через `vswhere` и падает обратно на VS 18 BuildTools, если он установлен.
Результат — `uniland.exe` в корне проекта.

Учебник по языку и по устройству порта — `docs/guide.md`. Справочник по встроенным
функциям с сигнатурами — `docs/stdlib.md`.

## Linux и FreeBSD

Этот порт на C — Windows-only: Win32 API, WinHTTP, GDI+, MCI, wide-API и MSVC. Под Linux и FreeBSD он нативно не собирается, готовых бинарников нет. Работающие варианты такие.

### Эталон на Go — нативный бинарник

Проверено кросс-сборкой отсюда: `linux/amd64`, `linux/arm64` и `freebsd/amd64` собираются с `CGO_ENABLED=0` и тегом `nogui`.

```sh
git clone https://github.com/name-cho/uniland-go
cd uniland-go
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -tags nogui -o uniland .
sudo install -m 755 uniland /usr/local/bin/
uniland run script.uni
```

- Python для блоков `python { }`: `sudo apt install python3` (Debian/Ubuntu), `sudo pacman -S python` (Arch), `sudo pkg install python3` (FreeBSD).
- Окна на Linux: нужны cgo и dev-пакеты — `sudo apt install gcc libgl1-mesa-dev xorg-dev libwayland-dev libxkbcommon-dev`, затем `go build -o uniland .`. На FreeBSD GUI эталона не гарантирован, собирайте с `-tags nogui`.
- Подробная установка (Debian, Arch, Termux, PATH, удаление) — в `docs/install.md` эталона.

### Наш `uniland.exe` под Wine

```sh
sudo apt install wine64      # Debian/Ubuntu
sudo pkg install wine        # FreeBSD
wine uniland.exe run script.uni
```

CLI-часть (`run`, `eval`, `check`, `fmt`, `lsp`) под Wine обычно работает. GUI (GDI+/MCI), WinHTTP и мосты к Python/Go/C под Wine не проверялись — на них рассчитывать нельзя.

### Почему нельзя просто «сделать make»

Порту нужен платформенный слой: POSIX-окна вместо user32/gdi32 (GTK, Qt или SDL), libcurl вместо WinHTTP, ffmpeg вместо MCI, `dlopen` вместо `LoadLibrary`, плюс замена MSVC-специфики в сборке. В этом репозитории такого слоя нет — это отдельная работа, а не флаг компилятора.

## Что умеет

- Лексер, парсер и дерево-интерпретатор: переменные, функции, замыкания, циклы, `try/catch/finally`, шаблонные строки, массивы, объекты.
- Длинная арифметика без внешних зависимостей (`bigint.c`), числа произвольной точности.
- Стандартная библиотека: строки, массивы, объекты, математика, JSON, файлы, время, `env`, `exit`, `argv`, `http_*`.
- Модули: `import "lib.uni"` и `import "lib.uni" as ns`, путь от файла-импортёра, кеш и защита от циклов.
- Трассировка: стек вызовов в тексте ошибки и режим `run -t` с порядком выполнения.
- CLI как у эталона: `run`, `eval`, `check`, `repl`, `fmt`, `lsp`, `-e`, `-i`, `-c`, `-d`, `-v`, `-h`.
- Байткод-VM: компиляция AST в инструкции и стековый движок, включается `UNILAND_VM=1`.

## Байткод-VM (`src/vm.c`)

Программа компилируется в массив инструкций (`op`, два `uint16`-операнда, строка,
указатель на метаданные `try`) и исполняется стековым движком с регистрами для
составных присваиваний. Покрыты переменные, функции и замыкания, `for`/`while`/
`for in`, `try/catch/finally`, `throw`, шаблоны, массивы, объекты, индексы и поля,
`++`/`--`, `+=` и родственные, `break`/`continue`, блоки `python {}` и `go {}`,
`import`. Ошибки в VM дают тот же текст и стек вызовов, что и дерево; `-t` печатает
трассировку и в VM.

Включается переменной окружения:

```
set UNILAND_VM=1
uniland run script.uni
```

По умолчанию работает дерево-интерпретатор. После переделки окружений и замеров
движки идут вровень: цикл на 1 000 000 итераций — 0,34 с на дереве и 0,26 с на VM,
`fib(24)` — 0,12 с на дереве и 0,16 с на VM (минимум из серии; разброс на этой машине
до 20%). VM выигрывает на циклах за счёт кэша переменных, но платит за кадры вызовов,
поэтому движок по умолчанию не менялся. Если конструкцию скомпилировать нельзя,
исполнение автоматически откатывается на дерево.

## Скорость

Три правки дали основной выигрыш — цикл ускорился примерно в 14 раз (с 4,9 с до
0,34 с), `fib(24)` — примерно вдвое:

- Имена переменных ищутся по хеш-таблице в окружении, а не линейным перебором
  связок со `strcmp`. На глобальном окружении это было до сотни сравнений на каждую
  переменную.
- Сами окружения и `BigInt` выделяются из арен, а не через `malloc` на каждое
  значение.
- Блок без объявлений (`while`, `if`, тело функции) больше не создаёт новое
  окружение, а аргументы вызова до 8 штук не аллоцируются в куче.

| тест | было (дерево) | стало (дерево) | стало (VM) |
| --- | --- | --- | --- |
| цикл 1 000 000 итераций | 4,86 с | 0,34 с | 0,26 с |
| `fib(24)` | 0,26 с | 0,12 с | 0,16 с |

Оставшееся узкое место — объект `BigInt` на каждую арифметику: числа до сих пор
представлены указателем, а не встроенным `int64`. Это следующий шаг, оценка эффекта —
10–15% на арифметике при заметном риске для всей семантики значений, поэтому он
вынесен в `docs/ROADMAP.md`.

## Мосты и интеграции

### Python (`src/pybridge.c`, `src/pyworker.py`)

Настоящий Python-процесс по протоколу эталона: JSON-строки через stdin/stdout, общий набор переменных на всё время работы.

- `python { ... }` и `pyexec(...)` исполняют код, `pyeval(...)` возвращает значение.
- `uni.x` в Python читает переменную UniLand, `uni.x = v` пишет её обратно, `uni.call("f", 21)` вызывает функцию UniLand.
- Вывод print из Python уходит в stdout интерпретатора, ошибки — в stderr.

Python ищется так: `UNILAND_PYTHON`, затем `python3.exe`, затем `python.exe` в PATH.

### C (`src/cbridge.c`)

```
let m = c_load("msvcrt.dll")
print(c_call(m, "strlen", "is", "hello"))
print(c_call(m, "pow", "ddd", 2, 10))
c_free(m)
```

- `c_load(path)` — адрес библиотеки, `c_sym(handle, name)`, `c_free(handle)`.
- `c_call(handle, name, sig, ...args)`: первый символ `sig` — тип результата, дальше типы аргументов: `i` — целое/указатель, `s` — строка, `d` — double. Результат: `i` — число, `d` — float, `s` — строка, `v` — null.
- Ограничения: аргументы в одном вызове либо все целые/строковые, либо все double (до 6 целых, до 4 double). Смешанные типы дают понятную ошибку.

### Go (`src/gobridge.c`, `src/goworker.go`)

`goeval`, `goexec` и блоки `go { ... }` исполняет постоянный воркер на yaegi — один процесс на весь запуск скрипта, поэтому переменные и объявления живут между вызовами.

- Предзагружены пакеты: `fmt`, `strings`, `strconv`, `math`, `sort`, `time`, `regexp`, `unicode`, `math/big`.
- `uni.SetInt/SetStr/SetFloat/SetBool/SetBig`, `uni.GetInt/GetStr/GetFloat/GetBool`, `uni.Call(name, args...)` работают через строковый RPC между Go и интерпретатором.
- Обратный мост: `gofunc("strings.ToUpper")` возвращает функцию UniLand, которая вызывает Go-функцию. Аргументы приводятся по типам параметров, результат — число, bool или строка.
- Первый запуск собирает воркер: `go build` в `%TEMP%\uniland-goworker-<pid>`, модуль `yaegi v0.16.3` подтягивается из кеша Go или из сети. Дальше запуск идёт без компиляции.
- `go { ... }` оборачивается в функцию, поэтому объявления внутри блока локальны для блока; обмен данными — через `uni`.
- Воркер кешируется в `%TEMP%\uniland-goworker-c\worker.exe` и переиспользуется между запусками; кеш сверяется по хешу встроенного исходника и пересобирается после правок `goworker.go`. Если `go` нет в PATH, `goeval`/`goexec`/`gofunc`/`go { }` возвращают ошибку с причиной.

Windows-нюанс: `go { }` в исходнике должен открывать скобку на той же строке (`go {`), а тело — идти со следующей. Открывающая скобка на следующей строке уйдёт в тело как обрезанный `{`.

### HTTP (`src/http.c`)

`http_get`, `http_post`, `http_put`, `http_delete` на WinHTTP.

- Возвращают объект `{status, body, headers}`; `body` с нормализованными переводами строк, ключи `headers` в каноническом виде (`Content-Type`).
- `post`/`put` сериализуют второй аргумент в JSON и отправляют с `content-type: application/json`.
- Ошибки соединения приходят как исключение: `HTTP GET failed: код 12029`.

### Форматтер (`src/fmt.c`)

`uniland fmt [-w] [-l] FILE` — тот же алгоритм, что у эталона: четыре пробела на уровень, отступ закрывающих скобок, verbatim-строки и блоки `python`/`go` не трогаются. `-w` пишет файл, `-l` печатает имя, если файл изменился, и выходит с кодом 1.

### LSP (`src/lsp.c`)

`uniland lsp` — Language Server по stdio: `initialize`, `initialized`, `shutdown`, `exit`, `textDocument/didOpen`, `didChange`, `formatting` с диагностикой из парсера и правкой форматирования.

### GUI (`src/gui.c`)

Win32 с wide-API, поэтому кириллица в окнах и диалогах корректная.

- `gui_window`, `gui_label`, `gui_button` (с колбэком), `gui_input`, `gui_get`, `gui_set`, `gui_run`, `gui_close`, `gui_on_close`.
- `alert`, `confirm`, `prompt`, `pick_file`, `pick_save`, `pick_folder`.
- `gui_image`/`gui_image_button` грузят PNG, JPEG, GIF, BMP и ICO через GDI+; размер можно не указывать — берётся из файла.
- Анимированный GIF проигрывается: кадры переключает таймер окна, `gui_gif` — тот же загрузчик с явным именем.
- `gui_video(path, w, h)` открывает файл через MCI, встраивает окно в GUI и запускает воспроизведение; закрытие окна закрывает MCI-устройство.
- `UNILAND_NOGUI=1` включает поведение эталонной сборки с тегом `nogui` (все GUI-функции возвращают ту же ошибку) — так гоняются golden-тесты.

## Лёгкий синтаксис

Старые формы остаются рабочими, поэтому golden-кейсы и токены эталона не меняются.

```
x = 5                    // без let
fn double(n) { return n * 2 }
if x > 1 { print(x) }    // скобки у условия необязательны
while x > 0 { x -= 1 }
for i in 0..3 { print(i) }   // диапазон вместо range(0, 3)
```

- `x = 5` для неизвестного имени создаёт переменную в текущей области; `+=`, `-=`, `*=` по-прежнему требуют, чтобы переменная уже была.
- `if`/`while`/`for` принимают и вариант со скобками, и без.
- `a..b` — включительный диапазон целых, работает везде, где ожидается массив; в `for ... in` даёт те же значения, что `range(a, b + 1)`.
- `let`/`const` остаются для явного объявления и констант.

## Проверка

```
python tools\run_all.py
```

`run_all.py` запускает все наборы и печатает итог по каждому:

- `run_golden.py` сверяет stdout/stderr/код возврата всех 16 кейсов `tests/compat/cases` с `tests/compat/expected`.
- `run_tokens.py` сверяет дампы токенов через `run -d` с `tests/compat/expected-tokens`.
- `check_fmt.py` проверяет идемпотентность форматтера и неизменность потока токенов на всех кейсах.
- `test_lsp.py` прогоняет initialize/didOpen/formatting/неизвестный метод/shutdown/exit.
- `run_import.py` — модули: слияние имён, `as`, вложенный импорт, повторный импорт, цикл, отсутствующий файл.
- `run_trace.py` — стек вызовов, `-t`, отсутствие трассировки без флага.
- `stdlib_demo.uni` — сверка справочника стандартной библиотеки.
- `vm_smoke.uni` — замыкания, рекурсия, `try/finally`, циклы, объекты; сверяется в обоих движках.
- `vm: …` — golden, модули, трассы и примеры повторяются с `UNILAND_VM=1`.
- `gofunc.uni` — обратный мост Go (пропускается, если `go` нет в PATH).

Тот же `run_all.py` гоняется в CI: `.github/workflows/ci.yml` собирает проект на
`windows-latest` и запускает наборы на каждый push в `main` и на pull request.
Корпус лежит в `tests/compat`, соседний `uniland-go` для прогона не требуется.

## Чего нет

- Дерево-интерпретатор остаётся движком по умолчанию: VM включается `UNILAND_VM=1` и идёт вровень (замеры в разделе про VM).
- У GIF фиксированная задержка кадров 100 мс — per-frame задержки из файла не читаются.
- Видео играет через MCI и системные кодеки: формат зависит от того, что установлено в Windows.
- Память не освобождается до выхода процесса; нативная сборка вне Windows не поддерживается.

Порядок работ по этим пунктам и оценки — `docs/ROADMAP.md`.
